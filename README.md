# RangeFinder: Predicting Ligand Property Ranges from Protein Pockets

An SE(3)-equivariant transformer that predicts, for a protein pocket, the range of
nine physicochemical properties spanned by the ligands compatible with it. Rather than
proposing or scoring individual molecules, the model describes the region of chemical
space compatible with a pocket, which can be used to narrow a ligand search before
docking, generation, or synthesis.

Given a pocket (a point cloud of protein atoms with chemical and evolutionary features),
the model predicts, for each of nine properties, an interval `[mu - 2*sigma, mu + 2*sigma]`
that summarizes the property values of the pocket's binders.

## The nine properties

| Property | Definition |
|---|---|
| MW | Molecular weight |
| logP | Octanol–water partition coefficient |
| HBD | Hydrogen-bond donors |
| HBA | Hydrogen-bond acceptors |
| TPSA | Topological polar surface area |
| Rotatable bonds | Number of rotatable bonds |
| Formal charge | Net formal charge |
| Aromatic rings | Number of aromatic rings |
| fsp3 | Fraction of sp3-hybridized carbons |

## Installation

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

`torch-scatter` and `torch-cluster` must match your installed `torch` and CUDA build;
install the matching wheels from the PyTorch Geometric wheel index if the default
`pip install` fails. ESM-2 weights (`esm2_t33_650M_UR50D`) are downloaded automatically
by `fair-esm` on first use.

## Data

The model consumes one compact `.npz` per pocket, plus small CSVs describing the
train/validation/test split and the per-pocket property targets. No data is shipped
with this repository; it is regenerated with the scripts in `scripts/`.

### `.npz` format (one per pocket)

| Array | Shape | Description |
|---|---|---|
| `positions` | `(N, 3)` | 3D coordinates of the `N` pocket atoms |
| `chem_features` | `(N, 46)` | Per-atom chemical/structural one-hots (element, residue type, bonding flags) |
| `esm_residue` | `(L, 1280)` | Per-residue ESM-2 embeddings for the `L` pocket residues |
| `residue_idx` | `(N,)` | Atom → residue index (`-1` for non-protein atoms) |

At load time the per-atom feature vector is `concat(chem_features, esm_atom)` where
`esm_atom = esm_residue[residue_idx]` (zeros where `residue_idx == -1`), giving a
`46 + 1280 = 1326`-dimensional feature per atom.

### Rebuilding the dataset

The pipeline requires the BioLiP2 annotation index and the corresponding protein
structures (obtained from the Protein Data Bank); the property targets are computed with
RDKit and the residue embeddings with ESM-2. Point the structure root at your local
structures via the `STRUCT_ROOT` environment variable. Run, in order:

```bash
python -m scripts.build_biolip_ligands        # ligand sets + property targets (CSVs)
python -m scripts.build_biolip_structures      # prepare pocket structures
STRUCT_ROOT=data/structures \
  python -m scripts.compute_pocket_pointclouds # pocket atoms + chemical features
STRUCT_ROOT=data/structures \
  python -m scripts.compute_esm_embeddings     # attach ESM-2 embeddings -> final .npz
python -m scripts.build_biolip_splits          # protein-grouped train/val/test splits
```

Outputs are written under `data/` (point clouds under `data/.../pointclouds_esm/`, CSVs
alongside). The split is grouped by protein so that structural views of the same protein
never span train, validation, and test.

## Configuration

All hyperparameters live in `model/config.py` (`Config` dataclass). The training entry
point `scripts/train_biolip.py` sets the reported configuration:

**Architecture**
- SE(3)-Transformer encoder: `num_layers = 4`, `num_heads = 4`, `lmax = 1`
- Hidden state per atom: `32` scalar (`0e`) + `16` vector (`1o`) channels
- Message-passing radius graph: `radius_cutoff = 5.0` Å, `num_radial_basis = 16`
- Input feature dimension: `46` chemical + `1280` ESM-2 = `1326`
- Prediction head: MLP to `18` interval parameters (mu, sigma for 9 properties) plus one
  auxiliary aromatic-present logit

**Objective**
- Generalized-IoU loss on the `mu ± 2*sigma` intervals (the differentiable surrogate for
  the range-IoU metric), combined across pockets with inverse-protein-frequency weights
- Auxiliary binary cross-entropy on the aromatic-present head, weight `lambda = 0.089`

**Optimization**
- AdamW, `learning_rate = 2.23e-4`, `weight_decay = 1e-4`
- `head_dropout = 0.245`, `trunk_dropout = 0.235`, `atom_dropout = 0.0`
- `grad_clip_norm = 3.97`, `ReduceLROnPlateau` (factor `0.5`, patience `10`)
- Atom-budget batching (`atom_budget = 80000` edges/batch), early stopping (patience `12`)
- `seed = 42`

## Training

```bash
python -m scripts.train_biolip [num_epochs]
```

Trains on the built dataset and writes the best-validation checkpoint under
`model/checkpoints/`. `num_epochs` is optional.

## Evaluation

```bash
python -m scripts.eval_biolip [--checkpoint-dir <name-or-path>]
```

Loads the best checkpoint and reports per-pocket range-IoU on the test pockets (those
with at least three known ligands), averaged over the nine properties. The metric is the
interval intersection-over-union between predicted and target intervals.
